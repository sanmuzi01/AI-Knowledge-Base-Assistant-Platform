# FDE（前线部署工程师）储备岗：怎么讲这个项目

代码怎么讲见 `docs/code-walkthrough.md`。这份只回答一个问题：**FDE 面试官想听到什么，你的项目哪些经历能对上。**

## 1. 先搞清楚这个岗位在招什么人

FDE 的日常：进到客户的环境里，弄清客户的真实问题，把产品接进客户已有的系统，部署上线，出问题现场排查，再把
客户的需求反馈给产品团队。所以面试官看的不是"你会写多少代码"，而是：

| 他想确认的 | 你的项目里对应的证据 |
|---|---|
| 能把模糊需求问清楚 | 你做过"用户到底要什么"的取舍（比如技能只让管理员维护、一次连接多项能力） |
| 会把产品接进客户已有系统 | 企业接口连接器：让助手查客户现有系统，URL / 认证由管理员配，模型不能传 |
| 能独立部署、排障 | Docker Compose 全套、启动配置校验、上线后验证步骤、你自己排过的线上问题 |
| 有安全和合规意识（客户最在意） | 数据隔离、SSRF 防护、脚本沙箱、短信防刷、限流 |
| 沟通清楚，不甩锅 | 能讲清"做了什么、没做什么、为什么" |

## 2. 开场：60 秒版本（背熟，但用自己的话说）

> 我做了一个多用户的 AI 智能体平台：用户配好自己的大模型 Key，建一个助手，给它挂上知识库和工具，就能对话；
> 回答会带来源，找不到资料就拒答，不瞎编。已经部署在阿里云 ECS 上，用 Docker Compose 跑数据库、缓存、向量库、
> API 和后台任务。
>
> 我最想讲的是"怎么让它能交付给客户用"这一面：企业接口连接器可以让助手查客户已有的系统，但 URL 和认证由管理员配置，
> 模型没有传网址的能力；生产环境启动时会检查配置，示例密码、弱密码直接拒绝启动；数据按用户隔离，有真实路由级测试证明。
> 上线后我也遇到过并解决了一些部署层面的问题，比如限流在 nginx 后面的真实 IP 问题、线上和本地数据库不一致导致技能商店是空的。

然后停下来，让对方挑方向追问。**不要一口气把功能列表念完。**

## 3. 四个故事（用"问题 → 我怎么判断 → 我做了什么 → 结果和遗留"讲）

下面每个都对应仓库里真实的提交和文件，面试官追问时可以直接打开。

### 故事 A：上线后技能商店是空的（环境差异）
- **现象**：本地导入了 75 个技能，线上商店里一个都没有。
- **判断**：线上和本地是**两套独立数据库**，我在本地导入的数据当然不会出现在线上；不是代码 bug。
- **做法**：写了服务器端导入脚本 `scripts/import_skill_pack.py`（`--admin --public --replace`），也保留了页面导入方式；
  文档里写清两种方法什么时候用哪个。
- **FDE 视角**：客户环境和开发环境的数据不同步，是交付里最常见的一类问题；我先确认原因是不是代码，再选最小的补救方式。

### 故事 B：限流在 nginx 后面可能失效（部署层的坑）
- **发现**：复盘限流代码时注意到，后端限流用的是 `request.client.host`；经 nginx 再进 Docker，后端看到的是网关地址，
  会导致所有用户共用一份额度。
- **诚实说明**：这是我**分析代码和部署结构发现的风险**，不是线上已经出过事故。别说成"线上事故"。
- **方案对比**：① `FORWARDED_ALLOW_IPS=*` 再改 nginx——要两处配置都对，漏一处用户就能伪造 IP；
  ② 只信任内网网段，从右往左取第一个非内网地址——nginx 配置不用动，伪造的 IP 在左边取不到。选了②。
- **落地**：`Dockerfile` 里设置，`tests/test_client_ip_proxy.py` 覆盖直连 / 两层代理 / 伪造 / IPv6，
  并且测试直接读 Dockerfile 里的取值，以后改坏会被测出来；生产环境设成 `*` 启动时会警告。
- **FDE 视角**：本地跑得好好的功能，放到客户的反向代理后面行为会变——这是部署类问题的典型。

### 故事 C：短信验证码防刷（防止费用失控）
- **现状**：已有每号码、每 IP 的限制；我逐项检查后发现 4 个缺口：全站没有总量上限（换号码换 IP 就能刷）；
  注册发码在查库前没限流；重置密码没有 IP 限流；验证码"错误次数"是先读后写，并发请求能绕过。
- **做法**：加全站小时 / 天上限、查库前限流、校验按手机号做原子计数、发送顺序改成先 IP 后号码
  （被封的 IP 不能占用别人号码的冷却）。
- **诚实说明**：默认阈值是按小规模站点估的，文档里写了要按实际用户量调；不要说"已经被攻击过"，除非确实发生过。
- **FDE 视角**：客户会问"被刷了谁买单"，这类成本和滥用问题必须提前想。

### 故事 D：技能脚本沙箱（信任边界的取舍）
- **问题**：想直接用网上现成的技能，但技能带脚本，等于让服务器执行陌生人的代码。
- **取舍**：独立容器（无外网、无密钥、只读文件系统、资源上限）；**默认关闭**；只有管理员导入审核过的才能运行；
  导入时静态检查脚本，商店里提前标"可运行 / 暂不支持"；再加一层网关，让 API 不在沙箱网络里，堵住"脚本反过来访问 API"。
- **诚实边界（主动说）**：容器层面的隔离**还没在真实 Docker 上跑过验收**，我写了一键验收脚本
  `scripts/sandbox_acceptance.py`，部署后要先跑通再对外开。主动承认边界比被追问出来可信得多。

## 4. 你的项目和 FDE 的距离：面试官很可能追问的

| 追问 | 建议回答 |
|---|---|
| 这是你一个人做的吗？用了 AI 辅助吗？ | 如实说。用了 AI 辅助编码，但设计取舍、部署、排障是我自己在做；然后马上用第 8 节的 10 个问题里挑一个讲透，用讲得清楚来回答。**不要回避，也不要夸大。** |
| 客户要私有化部署怎么办 | Docker Compose 一键拉起；模型 Key 客户自己配；数据都在客户环境；启动配置校验防止误配；备份脚本 `scripts/backup.py` |
| 客户的系统没有 API 怎么办 | 诚实说：连接器需要对方有 HTTP 接口；没有的话要先评估是让客户开接口、做数据导出到知识库，还是写适配层——这是 FDE 要现场判断的事 |
| 没有多公司（租户）隔离吧？ | 对，目前是"用户"级隔离，没有"公司"这一层。我评估过最小方案（成员表 + 一个用户只属于一家公司），还没做。说清楚现状比含糊带过好 |
| 上线后怎么发现问题 | `/health`、Prometheus 指标和告警规则、操作日志、后台"系统诊断"页；告警可推到飞书 / 钉钉 |
| 模型答错了怎么办 | 拒答阈值、来源可核对、评估集回归（`docs/evaluation.md`）、知识库健康报告 |
| 你最想改进什么 | 沙箱实机验收、多公司隔离、把同步路径继续迁到异步——都是有明确依据的，不是空话 |

## 5. 不要这样说

- 不要说"我做了企业级 / 高并发 / 高可用"。项目是单机 Docker Compose，规模是小规模上线，没做过压测结论以外的容量承诺。
  可以说"做过压测脚本 `scripts/load_test.py`"，但别报没测过的数字。
- 不要说"完全防住了 XXX"。说"做了哪几层防护，还有哪些边界"。
- 不要背功能列表。面试官记不住 30 个功能，记得住 1～2 个讲得透的故事。
- 不要说没做过的东西：多公司隔离、沙箱实机验证，都是"没做 / 没验证"。

## 6. 面试前 30 分钟自查清单

- [ ] 线上站点能打开，能用演示账号完整走一遍：登录 → 建助手 → 挂知识库 → 提问 → 看到引用来源。
- [ ] 演示账号的模型 Key 有余额（提前发一条消息试）。
- [ ] 编辑器里开好这几个文件：`http_connector_tool.py`、`access_control.py`、`config_validation.py`、`react_engine.py`、`space_search.py`。
- [ ] 能不看稿讲清：一次聊天的完整旅程；额度为什么在调模型**之前**检查；接口连接器为什么不让模型传 URL。
- [ ] 至少准备好一个"我发现问题 → 判断 → 处理 → 还剩什么"的故事（上面 A～D 选两个）。
- [ ] 想好三个反问：客户主要是什么行业和规模？部署形态是私有化还是云上？新人第一个月会跟哪类项目？

## 7. 一句收尾

"这个项目里我最有把握的，不是功能多，而是我知道每个功能的边界在哪、上线时会出什么问题，
以及我处理过的那几个具体的坑。这也是我理解的前线部署工程师最需要的能力。"
