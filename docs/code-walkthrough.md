# 代码讲解手册（给 HR / 面试官讲项目用）

目标：**不念代码，用"问题 → 方案 → 取舍"讲**，需要时能打开 5 个文件指给对方看。
下面所有文件名和函数名都来自当前代码，可以直接搜到。

## 1. 一句话架构

```
浏览器（Vue3 页面）
   │  HTTP / SSE 流式
   ▼
FasdtApi/  路由层：收请求、鉴权、限流           ← "前台接待"
   ▼
service/   业务层：聊天、知识库、技能、配额…      ← "各部门办事员"
   ├─ runtime/   智能体运行：思考→调工具→再思考   ← "大脑"
   ├─ rag/       知识库检索：找到相关资料          ← "资料室"
   ├─ tools/     工具：计算器、企业接口、图表…     ← "手和脚"
   └─ skills*/   技能：可导入的工作流程说明书       ← "岗位手册"
   ▼
models/    数据层：MySQL 读写                    ← "档案柜"
外部：向量库 ChromaDB、Redis、用户自己的大模型 API、独立的脚本沙箱容器（默认关闭）
```

**规模**：后端约 3.1 万行 Python（路由 4 千 + 业务 2.2 万 + 数据层 4 千 + 工具 0.8 千），
前端约 1.8 万行（Vue3 + TypeScript），测试约 1.1 万行、646 个用例。

## 3. 一次聊天的完整旅程（最值得讲的一条线）

用户在页面点发送之后：

1. **前端** `frontend/src/views/Chat.vue` → `api/chat.ts::sendStream`：用 SSE 流式接收，回答一边生成一边显示。
2. **路由层** `FasdtApi/chat.py`：按顺序做三道关
   - `require_limit`：限流（防刷）
   - `quota_service.enforce_quota_async`：额度检查，**超额在调用模型之前就拦下**，不会白花钱
   - `concurrency_guard`：同一用户同时最多跑几个助手
3. **业务层** `service/chat_service.py` → `service/runtime/agent_runtime.py`：
   - 拼系统提示词：助手设定 + **知识库检索结果**（带【来源N】编号）+ 长期记忆 + 已装的技能说明
   - `service/tools/executor.py::ToolExecutor` 组装推理引擎：用**用户自己的模型 Key**，只挂这个助手绑定的工具
4. **推理引擎** `service/runtime/react_engine.py`（LangGraph 状态图）：
   `思考 → 需要工具吗？→ 调工具 → 看结果 → 再思考 …→ 给出回答`，最多迭代 5 轮，防死循环
5. **每一步都推给前端**（SSE 事件：思考 / 调用工具 / 工具结果 / 回答），用户能看到过程
6. **收尾**：保存消息、写运行轨迹（`AgentRun` / `AgentStep`）、记 Token 用量；
   本月用量跨过 80% / 95% / 100% 时推一条提醒（`quota_service.check_and_notify_threshold_async`）

**讲给 HR 的版本**：
> 用户发一句话，先过三道关：是不是刷屏、这个月额度够不够、同时跑的任务多不多。过关后，助手会先去资料室找相关资料，
> 再决定要不要用工具，比如查企业系统，最后给出回答并标明来源。每一步我都做成了可以实时看到的，出问题也好排查。

## 4. 六段值得打开给人看的代码

### ① 推理循环 — `service/runtime/react_engine.py`
- **问题**：模型光会说不会做，怎么让它"想一步、做一步、看结果、再想"？
- **做法**：用 LangGraph 把流程画成图：`agent` 节点思考，有工具调用就走 `tools` 节点，没有就结束。
- **值得说的点**：`max_iterations` 防止无限循环；`cancel_event` 支持用户点"停止"；工具内部调模型的用量也汇总进总数，
  避免漏计费。
- **追问**：为什么用 LangGraph？→ 每个节点都能插入轨迹记录，可控、可观测，以后加审核节点、记忆节点也方便。

### ② 知识库检索 — `service/rag/space_search.py::search_spaces`
- **问题**：怎么让回答有据可查，找不到就老实说不知道？
- **流程**：**先校验权限** → 问题向量化一次 → 逐个知识库空间检索 → 合并、过滤已禁用的文档 → 可选重排序 →
  组装带 `【来源N】` 的上下文 → **命中太少或分数低于阈值就拒答**（`RAG_MIN_SCORE` 默认 0.2）。
- **一个体现思考的细节**：向量检索对"合同编号、型号"这类精确字符串不敏感，所以我单独把这类词
  （`_KEYWORD_TOKEN_RE`）拿去做关键词补充召回，纠正"编号搜不到"的问题。
- **追问**：为什么要拒答？→ 企业场景里"瞎编"比"不知道"更危险。

### ③ 企业接口连接器 — `service/tools/http_connector_tool.py`（FDE 岗重点）
- **问题**：让助手查客户已有的系统，同时不能变成"让模型随便访问任何网址"。
- **做法**：每个连接器动态生成一个有名字的工具（比如"查询订单状态"）。**URL、请求方式、认证头全部来自数据库里
  管理员预先配好的值，不接受模型传入**。
- **安全点**：每次请求前都重新做 SSRF 校验（DNS 可能变化，不能只信配置时那一次）；请求头加密存储；
  响应体设大小上限，避免几十 MB 的响应塞满模型上下文；请求带重试和熔断。
- **追问**：怎么防模型被诱导去打内网？→ 模型根本没有传 URL 的能力，加上每次请求的 SSRF 校验。

### ④ 数据隔离 — `service/access_control.py` + `tests/test_routes_isolation.py`
- **问题**：多用户系统最怕 A 看到 B 的数据。
- **做法**：所有"按 ID 取数据"都走统一入口 `get_owned_agent / get_owned_knowledge / ...`，
  取不到就当不存在（404，不暴露"存在但无权限"）；知识库空间另有 owner/admin/editor/viewer 四种角色。
- **证据**：`test_routes_isolation.py` 用真实 JWT、真实数据库、真实路由，验证跨用户访问一律 404。

### ⑤ 启动时配置校验 — `service/config_validation.py::assert_runtime_config`
- **问题**：生产环境最常见的事故是"带着示例密码、弱管理员密码上线"。
- **做法**：生产模式启动时检查占位密钥（`change-me` 等）、弱管理员密码、CORS/域名白名单未收紧、缺 Redis、
  加密密钥格式，**任何一项不合格就直接启动失败**，而不是悄悄带病运行。
- **FDE 视角**：这是"把踩过的坑写成自动检查"，交付给客户时能少出事。

### ⑥ 技能导入与脚本沙箱 — `service/skills_core/package_import.py`、`script_report.py`、`sandbox/runner.py`
- **问题**：想直接用网上现成的技能，但技能里带脚本，等于让服务器执行陌生人的代码。
- **取舍**：脚本放进**独立容器**（无外网、无密钥、只读文件系统、资源上限）；**默认关闭**；只有管理员导入并审核过的才能运行；
  导入时对脚本做**静态检查**，在商店里提前标出"可运行 / 暂不支持"；上传的配置不能指定任意目录（防读到 `.env`）。
- **诚实的边界**：容器层面的隔离还没有在实机上验证过，部署后要按文档做验收——**这个要主动说**，显得可靠。
- **文档**：`docs/skill-extension.md` 写了现状、缺口和扩展路线。

## 5. 技术选型：一句话理由

| 选型 | 理由 |
|---|---|
| FastAPI | 异步、自带接口文档，适合流式输出 |
| MySQL + SQLAlchemy | 数据关系清晰；同步/异步两套读写并存，正在逐步迁移到异步（边界写在 `docs/sync-async-boundary.md`） |
| ChromaDB 向量库 | 生产用**服务模式**：因为 API 和 Worker 是两个进程，内嵌模式不保证并发安全 |
| Redis（缺失时内存兜底） | 限流、缓存；本地开发不用装 |
| LangGraph / LangChain | 智能体编排，节点可控可观测 |
| Vue3 + Tailwind + Pinia | 前端组件化，主题用设计令牌集中管理，深色模式靠翻转色阶变量 |
| Docker Compose + Nginx | 一套命令拉起数据库、缓存、向量库、API、Worker；HTTPS 走宿主机 |

## 6. 三种时长的讲法

- **30 秒**：只讲第 3 节的"一次聊天旅程"，一句话一步。
- **2 分钟**：旅程 + 挑一个最对口的模块讲（FDE 讲 ③，后端讲 ②④，全栈再加前端流式）。
- **深挖**：对方追问哪块，就打开上面对应的文件，只指 1～2 个函数，讲"问题 → 做法 → 取舍"。

**打开文件的规矩**：事先在编辑器里把这 5 个文件开成标签页（`react_engine.py`、`space_search.py`、
`http_connector_tool.py`、`access_control.py`、`config_validation.py`）。不要现场翻目录，不要滚动读代码，
指着函数名和文档字符串讲就够。

## 7. 代码层面的常见追问

| 问题 | 回答要点 |
|---|---|
| 怎么保证不串数据 | 统一的 `get_owned_*` 入口 + 空间角色 + 跨用户隔离测试 |
| 怎么防越权 / 防滥用 | 限流、并发守卫、配额（推理前拦截）、接口连接器不接受模型传 URL、SSRF 校验 |
| 为什么同步和异步都有 | 项目分阶段迁移：聊天和大部分查询接口已经是异步，技能管理的部分写入、RAG 检索仍是同步，用线程池桥接，边界写在 `docs/sync-async-boundary.md` |
| 怎么测的 | 单元测试 + 真实路由级测试（真实数据库和 JWT）；改配置校验、隔离、配额都有对应用例 |
| 最难的 bug | 讲项目里记录过的：`base_url` 被多拼了一次 `/chat/completions`，导致所有绑了工具的智谱模型助手每次对话都 404，是做流水线真实联调时才发现的——**说明只测单点不够，要跑全链路** |
| 怎么处理大模型不靠谱 | 拒答阈值、引用来源可核对、工具只给白名单、最大迭代次数、用量上限 |
| 如果客户要私有化部署 | Docker Compose 一键拉起；模型 Key 由客户自己配；数据都在客户环境；启动配置校验防止误配 |

## 8. 演示前自查：这 10 个问题你能自己讲清楚吗

**这是最重要的一节。** 如果面试官问"这是你写的吗"，你的底气来自能讲清楚，而不是回避。

1. 用户发一条消息，后端依次经过哪几步？（第 3 节）
2. 额度为什么要在调用模型**之前**检查？
3. ReAct 循环里，什么时候结束？怎么防止死循环？
4. 知识库检索为什么要先校验权限，再检索？
5. 回答里的"来源 N"是怎么来的？找不到资料时为什么拒答？
6. 接口连接器为什么不让模型传 URL？
7. 两个用户的数据是怎么隔离的？怎么证明隔离有效？
8. 生产环境启动时会拦截哪些配置错误？为什么？
9. 向量库为什么用服务模式？
10. 脚本沙箱为什么默认关闭？还有什么没验证？

答不上来的，打开对应文件读一遍文档字符串，多数模块开头都有中文说明。
